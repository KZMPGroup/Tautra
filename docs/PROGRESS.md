# Progres Tautra

Dokumen ini adalah sumber kebenaran progres pengerjaan. Setiap sesi kerja dimulai dengan membaca file ini, lalu melanjutkan dari bagian pertama yang belum dicentang.

Spesifikasi lengkap: [`PRD.md`](PRD.md).

## Status singkat

- **Fase aktif:** Fase 0–3 lolos uji fisik pengguna. **Fitur layar tambahan (Fase 4 / F5 dan F6) dihapus seluruhnya atas keputusan pengguna 2026-10-28** (kursor KVM tidak bisa pindah saat fitur aktif; pengguna memilih tanpa fitur itu supaya tidak ada bug). Protokol v9. **Fase 5 (Service & Gaming Mode) dan Fase 7 (kompatibilitas + firewall) sudah ditulis dan lolos kompilasi, menunggu uji fisik.**
- **Langkah berikutnya:** jalankan `tools/hapus-driver-layar.ps1` di PC dan laptop untuk mencopot driver/layanan lama (sekali saja), lalu uji fisik Fase 5: pasang layanan dari halaman Input, uji kontrol di layar UAC/kunci, dan uji Gaming Mode otomatis saat game fullscreen.

## Rencana per fase

### Fase 1 — Discovery, Pairing, Auto Connect (F1)
- [x] Identitas perangkat: `device_id` UUID + sertifikat self-signed, kunci privat dienkripsi DPAPI
- [x] Penyimpanan perangkat trusted (certificate pinning)
- [x] QUIC (`quinn`) dengan mTLS: verifier khusus yang hanya menerima sertifikat ter-pin
- [x] mDNS `_tautra._udp.local` (advertise + browse) via `mdns-sd`
- [x] Pairing PIN 6 digit dengan SPAKE2 + konfirmasi HMAC yang mengikat fingerprint sertifikat TLS (anti-MITM)
- [x] Pemantau jaringan: `NotifyIpInterfaceChange` + `NetworkListManager` (kategori Private, daftar jaringan yang diizinkan)
- [x] Auto connect, reconnect backoff 0,5 → 10 dtk, heartbeat 1 dtk, putus setelah 3 dtk
- [x] Mode idle: discovery pasif setiap 30 dtk / event jaringan, tanpa thread berat
- [x] Handshake versi protokol, pesan "perbarui aplikasi" bila beda versi
- [x] UI: halaman Beranda (status, latensi) dan Perangkat (pairing tampil/masukkan PIN, hapus perangkat)
- [x] **Kriteria:** pairing PIN berhasil; setelah laptop restart / pindah jaringan lalu kembali, tersambung otomatis ≤5 dtk *(lolos uji pengguna 2026-10-26)*
- [x] Perbaikan kolom PIN: pindah otomatis ke kotak berikutnya, Backspace/Delete, panah, paste 6 angka

### Fase 2 — KVM (F2)

## Uji fisik Fase 0–1

Yang perlu disiapkan di **kedua** perangkat (PC dan laptop):

1. Rust toolchain MSVC, Node.js LTS, dan WebView2 (sudah ada di Windows 11).
2. Di folder `ui`: `npm install`, lalu `npm run tauri dev`. Perintah ini otomatis membangun `tautra-agent.exe` lebih dulu sehingga agent dan UI berada di folder `target\debug` yang sama. Untuk build release tanpa installer: `npm run tauri build -- --no-bundle`, lalu salin `tautra-ui.exe` dan `tautra-agent.exe` dari `target\release` ke satu folder.
3. Saat agent pertama kali jalan, Windows Defender Firewall akan bertanya: centang **Private networks** untuk `tautra-agent.exe` (port UDP 47800 dan mDNS 5353).
4. Pastikan jaringan rumah berkategori **Private** di kedua perangkat (Settings → Network & internet → properti Wi-Fi/Ethernet → Private network). Bila tidak, tambahkan nama jaringan di halaman Umum → Jaringan yang diizinkan.

Yang diverifikasi:

- **Fase 0:** setelah logout/login Windows, agent berjalan sendiri (ikon tray muncul bila UI build release; di build dev cukup cek proses `tautra-agent.exe`), dan halaman Beranda menampilkan status dari agent.
- **Fase 1:** di PC buka Perangkat → Tampilkan PIN; di laptop buka Perangkat → Masukkan PIN → pilih PC → ketik PIN. Keduanya harus tersambung otomatis setelah pairing. Lalu restart laptop, atau putus dan sambung Wi-Fi laptop: Beranda harus kembali "Tersambung" dalam ≤5 dtk setelah jaringan kembali. Latensi tampil di Beranda.
- Bila gagal, folder log ada di Umum → Buka folder log (`%LOCALAPPDATA%\Tautra\logs`).

## Uji fisik Fase 2

Persiapan: build release baru di PC, lalu salin `tautra-ui.exe` dan `tautra-agent.exe` ke laptop. Tutup Tautra lama di kedua perangkat (tray → Keluar) sebelum menjalankan versi baru. Versi lama dan baru tidak bisa saling tersambung karena protokol naik ke v2.

Yang diverifikasi:

1. Setelah tersambung, Beranda menampilkan kartu **Keyboard & mouse**. PC (tanpa baterai) otomatis jadi perangkat input; laptop diletakkan di kanan PC.
2. Buka **Layout layar**, seret kotak laptop ke posisi yang sesuai meja ; selama halaman terbuka, pita warna bernomor muncul di tepi layar yang bersambung pada kedua perangkat, geser (atau pakai tombol geser halus) sampai warna dan nomornya segaris, lalu Simpan. Layout yang sama muncul di laptop.
3. Dorong kursor PC ke tepi yang bersebelahan: kursor muncul di laptop, kursor PC tersembunyi. Ketik, klik kiri/kanan/tengah, scroll vertikal dan horizontal, tombol samping mouse, tombol media (volume, play/pause). Semuanya masuk ke laptop.
4. Geser kembali ke tepi laptop yang bersebelahan dengan PC: kursor kembali ke PC di posisi yang sesuai.
5. Hotkey: `Ctrl+Alt+F2` lompat ke tengah layar laptop, `Ctrl+Alt+F1` kembali ke PC, `Scroll Lock` mengunci kursor (tidak pindah lewat tepi), `Ctrl+Alt+G` Gaming Mode (kursor kembali ke PC dan terkunci).
6. Saat kursor di laptop, matikan Wi-Fi laptop: dalam ≤3 dtk kursor dan keyboard kembali ke PC.
7. Coba **Input → Tahan di tepi sebelum pindah** = 300: kursor baru pindah setelah didorong ke tepi sekitar 0,3 dtk.
8. Bila jendela administrator/UAC aktif di laptop, Beranda menampilkan peringatan bahwa Windows menolak input (diselesaikan di Fase 5 lewat service).

Bila gagal, kirim isi `%LOCALAPPDATA%\Tautra\logs` dari kedua perangkat.

## Uji fisik Fase 3

Persiapan: build release baru di PC, lalu salin `tautra-ui.exe` dan `tautra-agent.exe` ke laptop. Tutup Tautra lama di kedua perangkat (tray → Keluar) sebelum menjalankan versi baru. Protokol naik ke v5, jadi versi lama dan baru tidak bisa saling tersambung.

Yang diverifikasi (lakukan dua arah, PC → laptop dan laptop → PC):

1. **Teks:** copy teks di Notepad, paste di perangkat lain. Copy dari browser lalu paste di Word: format (tebal, link) ikut.
2. **Gambar:** `Win+Shift+S` ambil screenshot, paste di Paint perangkat lain.
3. **File kecil:** copy beberapa file + satu folder di Explorer, paste di Explorer perangkat lain. Isi folder ikut tersalin.
4. **File besar (lazy):** copy file >1 GB, paste di perangkat lain. Explorer menampilkan dialog salin Windows; file diambil saat di-paste.
5. **Drag-drop:** seret file/folder dari Explorer PC ke tepi layar menuju laptop sambil menahan klik kiri. Kursor pindah ke laptop dengan ikon file ikut terseret dan teks "Salin ke …". Lepas di folder mana pun, desktop, atau aplikasi (misalnya Word, browser upload): file tersalin ke situ dengan dialog salin Windows. Menahan Shift/Ctrl/Alt tidak mengubah apa pun: file tetap disalin dan file asal tidak disentuh. **Esc** saat menyeret membatalkan. Lepas di tempat yang tidak menerima file (misalnya taskbar): tidak terjadi apa-apa. Ulangi dari laptop ke PC (seret file di laptop ke tepi menuju PC).
6. **Progress:** transfer yang lebih dari 2 dtk memunculkan toast "Menerima file"/"Mengirim file", progress tampil di halaman **Clipboard & file** dan tooltip tray, lalu toast "Transfer selesai".
7. **Pengaturan:** matikan "Gambar" di halaman Clipboard & file, copy screenshot: tidak terkirim. Ubah batas ukuran ke 1 MB: teks/gambar >1 MB tidak terkirim. Batalkan transfer dari tombol ✕: transfer berhenti dan statusnya jadi Dibatalkan.

Bila gagal, kirim isi `%LOCALAPPDATA%\Tautra\logs` dari kedua perangkat.

### 2026-11-01 — Pilih jalur jaringan tercepat di background

- Hanya berjalan saat ada perubahan jaringan: alamat IPv4 lokal berubah, atau alamat perangkat lain (mDNS) berubah. Tidak ada pengukuran berkala.
- Dijalankan oleh sisi pendial yang diutamakan (device_id lebih kecil), 4 detik setelah jaringan tenang. Setiap alamat perangkat lain diukur dengan koneksi QUIC ringan ALPN `tautra-probe` (3 kali, ambil RTT terkecil), termasuk jalur yang sedang dipakai. Sesi yang berjalan tidak disentuh.
- Aturan pilih (revisi atas permintaan pengguna, bukan lagi minimal 30%): tiap jalur diukur 5 kali dan diambil median. Jalur Wi-Fi diberi penalti 0,5 ms karena ms-nya naik saat bandwidth penuh. Jalur Wi-Fi dikenali dari antarmuka lokal yang dipakai (GetBestInterfaceEx + GetIfEntry2, tipe IEEE 802.11) atau dari daftar alamat Wi-Fi perangkat lain di TXT mDNS `wl`. Pindah jika skor jalur terbaik lebih kecil dari jalur sekarang dengan selisih minimal 0,2 ms, atau jalur sekarang gagal diukur. Contoh: Wi-Fi 4 ms vs LAN 0,8 ms pindah ke LAN; LAN 5 ms vs Wi-Fi 2 ms tetap pilih Wi-Fi.
- Pindah memakai make-before-break: sesi baru tersambung penuh dulu. Sesi lama baru ditutup (SUPERSEDED) 1,5 detik kemudian, supaya kedua sisi sempat pindah.
- KVM tidak dimulai ulang saat sesi diganti untuk perangkat yang sama. `Kvm::session_started` mengirim `SessionCmd::Rebind` ke loop KVM yang sedang berjalan. Loop menukar koneksi untuk datagram gerakan mouse, writer stream KVM ikut pindah lewat `watch`, dan antrean pesan KVM dipakai bersama oleh stream lama dan baru. Status kontrol, posisi kursor, hook, dan layout tetap. Jadi perpindahan juga boleh terjadi saat kursor sedang di PC lain.
- Perpindahan hanya ditunda selama ada transfer file yang berjalan atau menunggu, karena transfer terikat ke koneksi lama.
- Agent mengirim status tenang ke manager jaringan lewat `NetHandle::set_quiet`.

### 2026-11-01 — Perpindahan jaringan di semua kondisi (drag-drop, clipboard, keyboard)

- Syarat "tenang" sebelum pindah dihapus seluruhnya (`SetQuiet` dan `is_quiet` dibuang). Perpindahan berjalan kapan saja, termasuk saat kursor di PC lain, saat drag file, dan saat transfer berjalan.
- Transfer file tidak mulai dari 0: penerima sudah melanjutkan dari byte terakhir (`stream_file` memakai `FileRequest.offset` dan menunggu koneksi hidup lewat `watch`). Yang baru: pengirim menyimpan checkpoint hasher BLAKE3 tiap 64 MiB dan saat stream putus, per (offer, index), maksimal 16 file, TTL 1 jam. Jadi menghapus di satu PC membuat PC satunya ikut menghapus, baik saat tersambung maupun saat baru bertemu lagi.
